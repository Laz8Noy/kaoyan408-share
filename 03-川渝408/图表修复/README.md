# 川渝408_优化版.html 图表故障诊断与修复

日期：2026-09-03
对象：`<DOWNLOADS_DIR>\川渝408_优化版.html`（1,192,542 字节，ECharts 5.5.1 内嵌单文件页面）
结论：**图表代码本身没问题；是"优化"时把内嵌的 ECharts 库弄坏了，导致全部 12 个图表只显示"📊 图表加载失败"兜底文案。原文件未改动，修复版见本文件夹。**

## 一、现象

- 页面"三、可视化图表"10 张图 + "五、历年分数线趋势"2 张图，全部不显示，只出现占位提示：
  `📊 图表加载失败 / ECharts库未加载（Safari安全限制）请用Chrome/Edge打开，或通过本地服务器访问`
  —— 注意：**这不是 Safari/浏览器的问题**，提示文案是误导。
- 连带现象：右上角深色模式按钮、"回到顶部"按钮失效；页面底部可能残留一大片压缩代码乱码文本。

## 二、根因（字节级定位）

该页结构本应是 3 段 `<script>`：ECharts 库 → 深色模式/回到顶部 → 主数据逻辑。
实际第 2 段被**插进了第 1 段（ECharts 库）代码的中间**（原文件第 603 行）：

1. `<script id="optimization-js">`（深色模式 + 回到顶部脚本）被插入到 ECharts 库 `saveAsImage` 功能一条 JS 字符串的正中间，即
   `title="'+(x&&x[0]||"")+'" />` 之后（字符串被拦腰截断）。
2. 该插块自带的 `</script>` 提前终止了 ECharts 库脚本；库**剩余约 183 KB 代码被丢到 `<script>` 标签之外**，变成页面正文文本（底部乱码来源）。
3. ECharts 库脚本因中间混入了 HTML 标签文本（`<script ...>`）而**整体语法错误、整段不执行** → 全局 `echarts` 从未定义。
4. 页面图表初始化代码有兜底：`if(typeof echarts==='undefined')` → 把所有图表容器替换成"加载失败"提示。

附带影响：深色模式/回到顶部代码也死在同一段脚本里；`renderR`、评级表、推荐器等主逻辑脚本不受影响（正常）。

## 三、修复内容（仅结构性修复，未改动任何图表配置/数据/文案）

1. 把误插入的 `<script id="optimization-js">` 整块**移到 ECharts 库脚本之后**，独立成段（库 → 深色模式 → 主逻辑）。
2. 去掉库代码在字符串断裂处（`'" />` 与 `</body>'` 之间）被插入的换行，让字符串恢复连续。
3. `<script>` / `</script>` 由原来错配的 3/3 中夹带截断，恢复为规范配平：3 开 3 闭，各段各归其位。
