### 1.1 已发现的 T4 典型错误模式（06 库 `line2026`）

实测 4 例，均为 `06` 库错、`04` 页对：

| 错误模式 | 实例 |
|---|---|
| 把**国家线**当成院线 | 中北大学 085410 库=264（国家线），实际院线 **319** |
| 混入**其它年份**的国家线 | 北京交通大学 库=273（这是 **2024** 年工学国家线），2026 实际 273 只对应计算机学院 |
| 混入**其它专业**的线 | 青海大学 库=284（这是该校 **医学** 105109 的线），工学专硕实为 **254**（B区国家线） |
| 取值来源未标 | 库值 `264(国家线,NC)` 的 `NC` 标记未在 `docs/口径.md` 定义 |

### 1.2 比对口径铁律

**必须按 `(学校 + 专业 + 学院)` 三元组比对，不能只按学校。**

反例（本仓库真实踩过）：北京交通大学 085410 人工智能在**三个学院各有不同的线** ——

| 学院 | 2026 复试线 |
|---|---|
| 101 自动化与智能学院 | 285 |
| 001 电子信息工程学院 | 326 |
| 002 计算机科学与技术学院 | 273 |
| 900 在职专业学位中心（非全） | 264 |

若只按学校比对，会误判为"数据冲突"（实际两条都对）。**2026-09-23 初版曾按学校比对得出"29 处冲突"，按三元组重算后仅 12 处**，其中 1 处（北交大）即此原因。

### 4.3 比对基线（2026-09-23 实测）

| 结果 | 条数 |
|---|---|
| 按三元组一致 | **139** |
| 不一致（= §4.1 的 12 例） | **12** |
| ├ 其中**真数据错误** | **2** |
| └ 其中「三元组错配」（两者皆对） | **10** |
| 学院名无法自动匹配（需人工） | 15 |

> **教训**：只按学校比对，必然把「不同学院 / 不同专业」误判成冲突。北交大是铁证——085410 在 3 个学院分别是 285 / 326 / 273。
> 因此 `06` 库的 `line2026` 虽存在 §1.1 的错配问题，但**大部分"页面 vs 库不一致"其实是页面的单值单行结构造成的**，不是库的数据错。

## 6. 操作规程（写进 CONTRIBUTING）

1. **发现冲突** → 先查本文件 §2 的四处仓库内源，找原始出处。
2. **仍不确定** → 按 §1 顺序联网取证：先试 T1 官方公告，打不开再用 T2 转载，最后用 T3 已整理源交叉印证。
3. **记录** → 把「校名 / 专业 / 学院 / 两个值 / 裁定值 / 依据 URL / 取证日期」追加到 §4.1。
4. **落库** → 修正正本（`06/data/schools/*.json`），并在 `line2026` 的原文串里保留口径标记，如 `319(院线,官方2026-03-24)`。
5. **禁止**：凭"哪个文件更新"或"数值看起来更合理"来裁定；禁止用 T4 覆盖 T1~T3。
