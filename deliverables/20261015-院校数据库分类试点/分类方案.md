# 分类与维护规则

目标：补充一条信息时，能知道它属于哪个招生项目、哪一年、哪类信息及哪个来源。学校文件继续采用 JSON；SQLite、Excel 和网页在后续正式迁移时统一作为派生物。

## 一、先找项目，再找年份和主题

一所学校有多个 `offerings`。每个项目明确学院、专业代码、方向和学习方式；后两项未公布时留空。项目 ID 依据这些身份字段生成，与旧数组的行号无关；专业未确定时不靠「AI方向」等关键词编造代码。

每个项目的 `annual_data` 按招生年份排列，分为：

| 新分类 | 内容 | 旧字段举例 |
|---|---|---|
| `examinations` 考试科目 | 英语、数学、专业课及来源原称 | `subjectClass`、`nnSubjects`、`subjectClaim2026` |
| `enrollment_plans` 招生计划 | 计划人数、原始说明、专项组成 | `plan2026`、明细 `plan` |
| `retest_results` 复试 | 分数线、复试人数、原始比率名称 | `line2026`、`linesByYear`、`retestCnt` |
| `admission_results` 录取 | 录取人数、最低/最高/平均分、比率 | `admitCnt/Min/Max/Avg`、`nnRate` |
| `subject_statistics` 单科统计 | 408、政治、英语、数学均分等 | `nn408avg`、候选明细的单科均分 |
| `recruitment_notes` 招生说明 | 一志愿/调剂说明及其他年度上下文 | `fill`、`fill2026` |

`records` 存放观察的口径和证据位置；主题中的 `record_id` 指回该记录。比如一志愿和调剂的录取人数来自不同记录，不因为学院和年份相同就合并。

## 二、学校层级的主题

| 分类 | 用途 |
|---|---|
| `school` | 校名、招生单位代码、地区、院校标签；代码沿用本地 crosswalk 映射的核实状态 |
| `changes` | 改考事件；采用记录里的「生效年份」，不采用旧集合名 `updates2027` |
| `research` | 导师与研究方向原文，尚未明确归属的导师不擅自挂到某个专业 |
| `sources` | 全校引用资料及考情链接；N诺、王道是来源，不是招生项目分类 |
| `quality` | 既有冲突、学校说明、未能安全归属的记录；不自动裁定 |
| `legacy_annotations` | 暂存旧的 S/C 分类、AI 标签、热度等，不作为新结构的核心分类 |

## 三、四条必须守住的边界

1. 学院和专业都必须匹配。只有学院相同、且该学院仅一个已建项目时，才允许暂挂到该项目，并在 `match_method` 标记 `unique_college`。学院名称仅规范中英文括号及空白，发生规范化时加 `_normalized` 标记；保留括号内学院/校区信息。记录明确写多个专业代码时禁止退回学院唯一匹配；未满足条件的记录进入待归属区。
2. 专业代码优先读取结构化专业描述。只有备注中恰好出现一个明确代码时才抽取；出现多个代码则留待确认，不按关键词猜。
3. 改考公告与年度科目分开。公告不自动覆盖上一年的科目，也不直接宣称下一年的最终招生目录已核实。
4. 对简单数字、带「约」的数字、显式加法分别解析。`50+1专项` 保留两个组成，`约181(96+85调剂)` 保留近似及调剂组成。复杂语句只保留原文，不取第一个数字冒充总数。

## 四、这次刻意保留的待办

- 成都信息工程大学跨学院参考行涉及 085411，学院归属不足，不挂到两条 085410 项目上。
- 同一条记录里原有的「已核实」属于历史资料的表述；本次统一标记 `not_rechecked`，没有做新的事实认证。
- 原文中不同统计总体的最大值、最低值和人数并不天然可比，不能只按字段名去重或相加。
- 旧数据缺少全/非全等身份信息，样例不补猜测值；正式迁移须先补齐关键项目身份或保留明确的未知状态。
- 深圳大学的 3 条主记录、青海大学的 2 个方向及重庆邮电大学的主记录均缺少可唯一抽取的专业代码，保持未知。青海大学两条明细虽然写085400，但尚不能据此安全挂接到两个主方向，仍待归属。
- 重庆邮电大学源主记录夹有不同学院/专业的统计；中北大学旧明细的 plan 字段疑似混入录取组成。具体原文位置写在 `sample_notes.json`，并随输出保存在 `quality.review_notes`。这些说明只揭示口径风险，不宣称已纠正事实。
