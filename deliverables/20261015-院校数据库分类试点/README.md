# 院校数据库分类试点

本目录用成都信息工程大学、湖北大学、深圳大学、广东工业大学、桂林电子科技大学、青海大学、中北大学、重庆邮电大学 8 所学校，验证按「招生项目 → 年份 → 信息主题」维护数据的可行性。旧库仍是当前网站的数据源；本目录是可检查、可重建的迁移样例。

实施步骤：先留存原始快照及哈希，再写防止串学院、串年份、丢原文的测试，最后实现转换与生成中文对照。已获确认的范围不包括个人重点关注、冲稳保，也不包含招生事实的重新联网核实。

## 从哪里看

- `分类对照.md`：给人看的 8 校分类结果，含不同学院、年度及统计批次。
- `schools/`：按新结构组织的 8 校 JSON。
- `evidence/`：来源记录、旧标签、逐字段迁移清单；与日常查看的学校 JSON 分开放置。
- `分类方案.md`：字段的归属、维护方式、迁移边界。
- `source_snapshots/`：逐字节复制的旧 JSON 和本次使用的院校代码映射。
- `source_manifest.json`：原始文件位置及 SHA256。
- `tools/migrate.py`：只依赖 Python 标准库的转换器。
- `tests/test_migrate.py`：分类、数字组成、冲突保留及完整性检查。
- `migration_report.json`：每校字段归位数量。
- `verification.json`：原库哈希、落盘数据完整性及重建一致性的本次检查记录。
- `sample_notes.json`：本批原资料中的分类风险，逐条指向源记录；不是新的招生事实裁定。

本次结果：8 校、15 个招生项目；1,150 个原始数据项（含 null 和空容器）均有保留位置。19 项测试通过。成信工 1 条参考记录、青海大学 2 条明细、中北大学 1 条参考记录共 4 条保留待归属；原有冲突全部保留。落盘数据的独立检查结果见 `verification.json`。

这批覆盖了三类容易误并的情况：同校多个学院、同学院多个方向、专业或招生单位代码缺失。学院名只规范中英文括号和空白，不删除括号内内容、不做模糊匹配；记录若明确出现多个专业代码，禁止退回「学院唯一」来强行归属。

## 重建与检查

在本文件所在目录执行（Python 3.10 及以上）：

```powershell
python -X utf8 tools/migrate.py
python -X utf8 -m unittest discover -s tests -v
```

首次执行会创建 `schools/`、`evidence/`、`分类对照.md` 和 `migration_report.json`。重建已有产物需加 `--replace`，转换器会先把旧产物复制到本目录的 `.backups/`。

## 使用边界

这里把既有资料重新分类，没有重新核实招生事实。相同项目的不同批次、统计总体及来源各自保留；不通过平均、取最新一条或相加不同来源的方式消除冲突。缺少学习方式、专业名称等信息时保留空值，不猜。

每条数值保留 `raw`；每条观察保留 `record_id`，可到对应 `evidence/` 文件的 `records` 找到原始位置、口径和原有核实表述。该文件的 `coverage` 逐项记录旧字段的位置；暂未整理的字段保存在 `legacy_annotations`。其中的目标指针按学校 JSON 与证据 JSON 合并后的对象解析。试点确认前不要用它替换旧库或现有生成脚本。
